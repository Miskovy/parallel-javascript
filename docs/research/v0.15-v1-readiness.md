## Reduced release-candidate validation plan

On existing Fedora and Windows machines, use installed supported Node 22/24
binaries without changing defaults. For the exact candidate tree run build,
npm test, test:types, typecheck:compat, lint, format:check, test:docs,
test:package and git diff --check. The package test packs, installs in an unrelated
directory, checks ESM/TypeScript/error/worker paths and executes all new examples.
Use npm.cmd on PowerShell if necessary. Save command exit codes, actual counts,
Node/V8/npm/OS/arch/availableParallelism, tarball hash and source hashes to a new
artifact. Never overwrite v0.1–v0.15 evidence. A failed cell must stay recorded.

Keep the matrix to two Node lines and Linux/Windows. No benchmark replay, full
crypto/compression campaign, new workload or release publication is part of this
plan. Validate untested hosts only if deciding to advertise them later.

## Proposed definition of PJS 1.0

PJS 1.0 would be an ESM runtime for explicitly registered, trusted Node CPU tasks,
with bounded admission to persistent workers, defined clone/transfer/shared-input
ownership, predictable failure/caller-settlement/shutdown behavior, and an
installable typed core. Range coordination and binary result-credit controls can
remain separately documented experimental facilities until explicitly promoted.
