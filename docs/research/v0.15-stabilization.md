## ERROR MODEL

## TASK EXECUTION CONTRACT

Execute one trusted registered file-module export through bounded admission;
clone input by default and resolve its caller-visible output. Module globals persist
per worker. Type parameters assert the separate export's schema. Tasks finish
owned asynchronous work before returning. No closure serialization, eval or sandbox.

## CALLER SETTLEMENT VS PHYSICAL EXECUTION

Cancellation/timeout can settle a caller while execution still occupies its worker.
Late results do not settle twice. Active strict reservations remain until physical
end. Zero pending callers alone does not establish quiescence.

## CANCELLATION

Pre-abort rejects without admission. Queued abort removes work/releases claims;
active abort does not preempt or reverse transfers/side effects. Parent failure
cancels sibling callers. Consumer break closes production and drops buffers;
posted batches may finish. No cooperative cancellation added.

## TIMEOUTS

run installs its timer during admission before dispatch: remaining startup, queue,
execution and result transport are included. Ranges use one start-time deadline
including generation/assembly; streams include consumer delivery waiting. Processing
after final yield is outside the completed operation. startupTimeout is per worker.
All deadline observations require host event-loop progress, not hard real time.

## SHUTDOWN

Default graceful mode closes admission, finishes whole accepted operations and
active cancelled executions, waits for stream delivery, then stops workers. Open
abandoned streams/uncooperative tasks can hold it indefinitely. Choose non-draining
mode initially when termination is required. First call fixes mode; subsequent
calls share its promise. Submissions during/after shutdown reject.

## WORKER FAILURE / REPLACEMENT

Unexpected exit/protocol failure fails affected work and replaces the worker within
the lifetime budget after its old thread exits. No task replay. Bootstrap failure
or exhausted restarts is fatal. Task/contract errors normally leave workers usable.
Exactly-once cleanup remains covered by lifecycle and retained platform tests.

## QUEUE SEMANTICS

maxQueue bounds waiting logical work; overflow rejects with PjsQueueFullError,
not a broken-runtime signal. No hidden waiting. Bound application offers/backoff,
absorb bursts or shed load. Queue depth is not compute capacity.

## WORKER COUNT GUIDANCE

Fixed workers are a resource policy. availableParallelism is not optimality proof.
Physical cores, SMT, native threads, memory and application headroom matter.
Measure throughput with timer/filesystem tails; no automatic sizing added.

## TASK GRANULARITY GUIDANCE

Tiny work loses to overhead; coarse work can amortize it. Compare equivalent
serial/native async controls, preparation, transport, warm execution and consumption.
Retain variability. No universal byte threshold or speedup claim.

## CLONE

Default simple ownership/separation with copy cost. Queued references are retained
until dispatch; do not mutate/resize/externally transfer them before settlement.
SAB retains shared semantics through structured clone.

## TRANSFER

Input lists and output envelopes move entire ArrayBuffer backing at successful
posting, detaching all sender views. Queued cancellation preserves attachment;
post-dispatch failure cannot restore ownership. Recycling is an application protocol.

## SHARED INPUT

sharedReadonly copies supported visible numeric bytes once into compact SAB backing.
Reuse its result; readonly does not freeze it. Keep aliases immutable while workers
may read, including after caller cancellation. GC owns lifetime.

## COUNT BACKPRESSURE

Per-stream buffered plus admitted-unsettled logical results obey the count cap.
Zero-byte results still consume count.

## BYTE BACKPRESSURE

Per-stream visible binary credit is independent of scheduling. Inputs, worker
heaps/scratch/native allocations, backing size, transport copies, consumer retention
and RSS are outside it. Aggregate streams can exceed one stream's cap.

## EXACT RESULT CONTRACT

Declare bytes before admission; worker validates equality, including rejecting
smaller output. Known-length decompression supplies retained real evidence; a new
generic transform example exercises this without codec logic.

## UPPER-BOUND RESULT CONTRACT

Reserve maximum M, execute, validate actual A ≤ M before transport, reconcile
deliverable success on arrival, refund M−A and retain A until yield.

## REFUND SEMANTICS

Positive slack increments refund metrics; equal-size success reconciles without
a positive refund. Yield/failure release is not refund. Discarded late success
does not reconcile. Active cancellation holds credit until physical end.

## EXTERNAL RESOURCE CONTRACTS

PJS can correctly enforce a wrong declaration. Stock-zlib/zlib-ng qualification
established the boundary: matching workload/library configuration supplies a safe
bound; PJS enforces it. No codec helper or native addon enters the runtime.

## STREAMING SEMANTICS

Eager single-consumer completion-order partition/output delivery. Count and optional
byte credits gate production. Failure discards undelivered buffers; yielded values
remain consumer-owned. Close abandoned iterators explicitly.

## ORDERING MODEL

Collection orders partitions; maps order elements; streams deliver completion order.
Reconstruct using partition index/range/offset. Application reorder buffers and
retained reconstruction memory are outside PJS credits; the binary example tests it.

## DEFERRED NON-BLOCKERS

Hiding unsupported snapshot declarations, narrowing experimental binary backing
types before promotion, freezing selected diagnostics, and unqualified macOS/ARM64/
other Node/CJS. Ordered streams, work stealing, auto-sizing, cooperative cancellation
and more workloads are optional capabilities, not existing-promise blockers.

## PROPOSED DEFINITION OF PJS 1.0

An ESM runtime for explicitly registered trusted Node CPU tasks, with bounded
admission to persistent workers, defined clone/transfer/shared-input ownership,
predictable errors/caller settlement/shutdown and an installable typed core.
Range coordination and binary-credit controls can remain separately experimental.
