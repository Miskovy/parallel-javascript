## Preservation, limits and release progression

All **25** runtime source files and the **128** historical evidence files captured
by Fedora retain their original SHA-256 hashes. The Fedora validation JSON itself
is also preserved. Runtime sources and package manifests still match the exact
stabilization commit. No large historical benchmark campaign was rerun.

The Node policy remains `^22.13.0 || ^24.0.0`: Node 22.13+ within 22.x and Node 24.x.
Fresh Fedora package evidence covers 22.23.3, 24.13.1 and 24.21.0; this fresh
Windows qualification covers **24.21.0**. **Node 22.13.x is not freshly
release-qualified.** Do not infer qualification of every patch, other Node majors,
macOS or ARM64. Minimum-version testing and a fresh Windows Node 22 package cell
remain appropriate RC hardening work. macOS ARM64 is desirable before final 1.0
and requires an explicit support decision, but does not block this v0.15 boundary.

The [Windows validation artifact](../../benchmarks/results/validation-v0.15-windows.json)
contains exact commands, exit codes, counts, API snapshot, full package metadata,
consumer/example results and preservation hashes. After committing this evidence,
the authorized release workflow is: clean final build/tests/dry-run, rebuild the
canonical tarball, create and verify an annotated `v0.15.0` tag on the evidence
commit, push it, and prepare a GitHub pre-release with the canonical tarball and
hash. npm publication is excluded. No `v1.0.0-rc.1` implementation has begun.
