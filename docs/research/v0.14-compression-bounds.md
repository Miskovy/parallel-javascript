# v0.14 raw-deflate reservation bound

## Stock zlib qualification

The benchmark fixes windowBits=15, memLevel=8, Z_DEFAULT_STRATEGY, no dictionary,
and level 1/6/9. One independent block ends with Z_FINISH, without intermediate
flushes. For a nonnegative safe integer input length N, reserve:

```text
B(N) = N + floor(N / 4096) + floor(N / 16384)
         + floor(N / 33554432) + 7
```

This is the default-parameter branch of deflateBound, with raw wrapper length
zero. The corresponding zlib wrapper contributes six bytes, giving the familiar
constant 13. Default gzip contributes eighteen, giving constant 25; custom gzip
headers/dictionaries require separate accounting. These other APIs are not enabled.
Use arithmetic floor division rather than JavaScript signed 32-bit shifts;
reject input or result sums outside the safe integer domain.

The [zlib manual](https://zlib.net/manual.html) establishes the finish/no-flush
restriction; extra flushes can exceed this bound. The implementation arithmetic
is visible in [zlib 1.3.1 deflate.c](https://github.com/madler/zlib/blob/v1.3.1/deflate.c#L772)
and the exact installed build's
[Node 24.21.0 bundled deflate.c](https://github.com/nodejs/node/blob/v24.21.0/deps/zlib/deflate.c).
The latter uses deflateBound_z with overflow checks and the same default branch.
It was fetched and inspected directly because the browser could not fetch that file.
Installed process.versions.zlib is 1.3.2.1-motley-8002e91, not stock 1.3.1.
Fixtures are empirical regression checks; the implementation contract supplies
the proof. Node does not expose deflateBound as a JavaScript function.

## Node mapping and memory

[Node's binding](https://github.com/nodejs/node/blob/v24.21.0/src/node_zlib.cc)
negates windowBits for DEFLATERAW, initializes deflateInit2 and calls native
deflate. [Node's JS implementation](https://github.com/nodejs/node/blob/v24.21.0/lib/zlib.js)
uses Z_NO_FLUSH/Z_FINISH defaults and repeats writeSync when the output chunk fills;
changing output buffer capacity does not introduce additional flush markers.
The harness explicitly supplies these options. The current selector accepts the
exact stock identifier `1.3.1` and the researched Motley identifier
`1.3.2.1-motley-8002e91`. Their formula and all historical Windows numbers are
unchanged. Arbitrary suffixes and future versions require separate qualification.

Buffer.from(shared.buffer, offset, length) makes a view without copying; the
harness tests backing identity and aliases. Buffer.from(typedArray) copies and
is not used for the shared view. Native deflate still copies input into its
sliding window (read_buf/fill_window); shared input removes transport cloning,
not codec memory movement. Compact Uint8Array output introduces one deliberate
copy so transfer owns precisely the visible backing and never a pooled slab.

The [Node zlib documentation](https://nodejs.org/download/release/v24.21.0/docs/api/zlib.html)
documents asynchronous use of the shared threadpool. Native synchronous deflate
is a direct codec call; the inspected standard path creates no inner thread pool.
SIMD optimizations are not extra threads. No Brotli or hardware-QAT path is selected.

## Enforcement and validation

Bound validation covers empty/1-byte/boundary fixtures, repeated/structured/random
data, multiple seeds, 1 KiB through 4 MiB, and levels 1/6/9. Raw artifact:
compression-v0.14-bound-validation.json. Each output inflates and matches input.
The PJS worker binary contract is the final enforcement layer. Lifecycle tests
deliberately declare one byte less than a known fixture needs, and require
PjsBinaryResultContractError; the safe formula is never adjusted to fit samples.
Exact inflate similarly requires its declared original visible byte length.

## zlib-ng qualification

**Source-derived:** [zlib-ng 2.3.3 deflate.c](https://github.com/zlib-ng/zlib-ng/blob/2.3.3/deflate.c)
initializes a broad conservative value, then narrows it using stream state,
wrapper mode, window size, hash configuration and architecture hooks. The raw
wrapper contributes zero. The source's default path with `NO_QUICK_STRATEGY`
returns:

```text
Bng(N) = N + floor(N / 16) + 7
```

At 1 MiB it is **1,114,119 bytes**. This is the codec's guaranteed bound,
not a maximum observed output plus a margin. The selected path does not branch
on levels 1, 6 or 9; level 0 has a special case only in the earlier conservative
branch and is outside the benchmark qualification.

The [Fedora 44 package recipe](https://src.fedoraproject.org/rpms/zlib-ng/blob/f44/f/zlib-ng.spec)
builds compatibility mode with `ZLIB_COMPAT=ON` and `WITH_NEW_STRATEGIES=OFF`.
The [upstream CMake configuration](https://github.com/zlib-ng/zlib-ng/blob/2.3.3/CMakeLists.txt)
maps the latter setting to `NO_QUICK_STRATEGY`. This is why the no-quick branch
applies; the compatibility version string alone does not establish it. The two
inspected Fedora patches concern RISC-V build detection and the compatibility
`FAR` macro, and do not alter this bound. Their hashes and source URLs are
retained with continuation validation evidence.

The earlier branch computes
`N + ceil(N / 8) + ceil(N / 64) + 5`, followed by wrapper handling. It applies
when the architecture requires a conservative result, the window is not the
maximum, or `HASH_BITS < 15`. It is not selected merely to cover uncertainty.
The inspected [deflate.h](https://github.com/zlib-ng/zlib-ng/blob/2.3.3/deflate.h)
sets `HASH_BITS=16`; initialization stores the supplied 15-bit window. memLevel
controls literal storage allocation, while this path's hash width is a constant.
Qualification nevertheless fixes memLevel at 8.

Without `NO_QUICK_STRATEGY`, the source uses separate quick-strategy overhead
and small-input corrections. That build is **not qualified** by this harness.
`deflateBound_z` is not required or used for the installed 2.3.3 compatibility
contract: the diagnostic calls its exported `deflateBound` with bounded lengths.

## Why the formulas differ

**Source-derived:** the two implementations declare different maxima under these
settings. zlib-ng's no-quick contract allows approximately 6.25% expansion,
whereas the stock default contract is much tighter. This does not imply measured
outputs expand that much, or prove the stock maximum unsafe for every zlib-ng
input. It establishes which guarantee is available from the executing codec.

**Native-diagnostic-derived:** every representative raw bound at levels 1/6/9
matches the selected zlib-ng formula exactly, including empty input, small
boundaries and 8 MiB. Matching samples validate the selector; the library
contract and branch derivation supply its justification.

## Wrapper and parameter assumptions

Both benchmark contracts accept raw deflate only: windowBits 15, memLevel 8,
default strategy, levels 1/6/9, no dictionary, Z_NO_FLUSH intermediate behavior
and Z_FINISH finalization. The pure selector rejects changed parameters,
dictionaries and zlib/gzip wrappers. Wrapper observations are retained solely
as diagnostic references: fresh zlib adds six bytes and default gzip eighteen.
Custom gzip headers and dictionaries need separate accounting.

The installed header's `deflateBound` contract permits Z_NO_FLUSH/Z_FINISH and
warns that other flush modes can exceed the declared bound. Node's raw binding
negates the window size. Its output-buffer refill loop does not introduce
intermediate flush markers. Every model uses the same explicit options.

## Architecture-specific hooks

**Source-derived:** `S390_DFLTCC_DEFLATE` selects IBM Z hooks in deflate.h.
Outside that branch, `DEFLATE_BOUND_ADJUST_COMPLEN` is a no-op and
`DEFLATE_NEED_CONSERVATIVE_BOUND` is zero. The Fedora recipe enables DFLTCC only
for s390x. This x86_64 RPM cannot take that architecture path. SIMD dispatch
does not select an alternative bound hook. Other architectures remain unqualified.

## Codec detection and failure behavior

`codec.mjs` distinguishes implementation family, compatibility version,
implementation version, build profile and bound contract. A zlib-ng suffix can
never select the stock contract. The only accepted zlib-ng profile is
`1.3.1.zlib-ng`, implementation 2.3.3, Fedora 44 x86_64 compatibility mode with
new strategies disabled. `checkZlib()` additionally verifies the installed
`zlib-ng-compat` and development RPMs are exactly `2.3.3-3.fc44.x86_64`, compares
library/header contents with RPM file digests, checks Node's shared-zlib linkage,
and runs the native diagnostic before admitting work.

Unknown versions, ambiguous linkage, changed library/header contents, unsupported
builds or native/formula disagreement throw a qualification error. A version
string or user-provided environment variable cannot opt an unknown installed
build into a campaign. The first check is cached within each host process,
outside measured trials. Pure tests use explicit deterministic codec descriptors.

All bound arithmetic uses nonnegative safe-integer validation and BigInt division
and sums before conversion. Exact overflow checks near the JS safe-integer limit
require no large buffer allocation. Native diagnostics stop at 8 MiB and cannot
validate arithmetic in the multi-terabyte range.

## Native diagnostic method

The research-only C helper includes the installed zlib.h and uses `dlopen` on
the exact real library path listed in Node's own process report. `dladdr` confirms
the bound symbol comes from that path. Node's `libnode` imports the codec symbols;
its shared-zlib configuration is true. Header/library versions, RPM digests,
compiler invocation, helper linkage and source hash are recorded. The helper
adds no addon, runtime dependency or shipping native component; its executable
is created in a temporary directory and removed after the probe.

The evidence is stronger than independently resolving `-lz` for a helper:
both processes load the same verified library file. Build predicates are tied
to the exact inspected RPM recipe and confirmed by its native API; no claim of
qualification for an arbitrary zlib-ng compatibility build follows.

The new native diagnostic records 37 lengths × three levels = **111 raw-bound
comparisons**, plus **333 actual compression/round-trip checks** over high,
moderate and poor data. A further 222 native wrapper-reference observations
validate fresh zlib/gzip wrapper offsets. The unchanged 324-fixture campaign is
rerun into a new artifact under the selected bound.

## Cross-platform implications

**Benchmark inference:** compare capacities in safe maxima and actual/maximum
utilization. The Fedora maximum is larger, so poor data can refund meaningful
slack even when its compressed output barely differs from original length.
Larger refunds do not demonstrate a runtime improvement. Admission, waiting,
occupancy and pre-delivery progress must be remeasured with the selected contract.

Windows raw artifacts and measured numbers are retained unchanged; they used
the previously researched stock-style Motley formula. The initial stopped
Fedora report and its fixtures also remain immutable. New qualification evidence
does not retroactively qualify that initial attempt.

PJS enforces an application-supplied number. Trustworthy bounded execution
requires both the runtime invariant and the external workload/library contract
used to calculate that number. PJS can enforce an incorrect declaration exactly;
codec knowledge belongs to the workload, not the runtime.
