## Native Argon2 finding

The standalone `argon2-probe.mjs` reproduces 197–215 ms synchronous submission
per async request on Node 24.13.1 / OpenSSL 3.5.7. Four submissions delay the timer
until 822–840 ms. Scrypt control submissions return in 0.01–0.14 ms. Classification:
**crypto API issue**. Architectural owner: Node/OpenSSL integration, not PJS.
This matches [upstream issue #62861](https://github.com/nodejs/node/issues/62861),
which is closed upstream. Preserve affected-build evidence, qualify conclusions,
and reproduce on a confirmed fixed build before proposing a product around it.
No Node or PJS implementation was changed; no new upstream issue was posted.

## Measurement limitations confirmed

The event-loop histogram can miss the first synchronous burst, despite priming
and draining. The independent timer, ELU and no-PJS submission probe expose that
stall. Classification: **benchmark issue**. Do not use a near-10 ms histogram
value to dismiss a hundreds-of-milliseconds timer stall.

The main process retains allocations across cells: sampled RSS peaks near 1,958
MiB and remains high in some subsequent smaller workloads. Classification:
**benchmark issue**, not evidence of a PJS leak. Use fresh-process attribution for
any future claim about per-workload memory savings.

## Runtime modification gate

No PJS runtime correctness bug was found in the completed campaign. No source changes,
special crypto task, native addon owned by PJS, scheduler tuning, protocol change,
or new public primitive is needed to execute this research. Optional bcrypt is an
existing trusted native package installed only for comparison.

If later evidence warrants runtime changes, first record a minimal reproduction,
measured impact, candidate solutions, and the architectural owner here. A proven
correctness fix additionally needs a regression test before implementation.
