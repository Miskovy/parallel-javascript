Motley identifier retain the original formula and **1,048,903 bytes at 1 MiB**.

Before a zlib-ng host campaign, the guard verifies Linux/x86_64 shared linkage,
the exact RPM version/release and library/header digests, then validates all
representative native bounds. Every process performs its own check before
admission; its result is cached outside timed trials. No override admits an
unqualified codec. An explicit negative entrypoint check confirmed an unknown
codec fails before a campaign artifact is created.

All formulas reject invalid lengths and exact safe-integer overflow. The pure
contract rejects unsupported wrappers, dictionaries, levels, window/memory
settings, strategies and flush behavior. No codec metadata or knowledge was
added to PJS result credits or public API.

## Architectural consequence

Bound tightness affects initial admission, reservations, refund size and waiting.
Fedora capacities are expressed in its own safe maxima. Incompressible data no
longer has Windows's near-100% maximum utilization simply because this codec's
declared maximum is larger. Increased slack must not be attributed to a PJS
performance improvement.

Bounded execution correctness spans the runtime invariant and the external
library contract. The workload supplies trustworthy declarations; PJS enforces
them. This remains a benchmark/recipe concern and supplies no justification for
`@pjs/compression`, a new runtime primitive or v0.15.
